# B站关注时间一键查询

> 粘贴一个 UP 主的主页链接，查出**你是哪一天关注 TA 的**。
> 还能拉取你的全部关注列表，排序、按年筛选、导出 CSV / JSON。
> 所有查询参数都能在设置面板里调，数据不离开浏览器。

一个 Tampermonkey（油猴）用户脚本 + 一个 GitHub Pages 落地页。

- 🚀 **落地页（一键安装）**：<https://molacktime.github.io/bili-follow-time/>
- 📦 **仓库**：<https://github.com/MolackTime/bili-follow-time>

## 安装

### 方式一：一键安装（推荐）

1. 安装浏览器扩展 [Tampermonkey](https://www.tampermonkey.net/)
   （[Edge 商店](https://microsoftedge.microsoft.com/addons/detail/tampermonkey/iikmkjmpaadaobahmlepeloendndfphd) ·
   [Chrome 商店](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo)）
2. 打开落地页 <https://molacktime.github.io/bili-follow-time/>，点「安装用户脚本」
3. 打开任意 B 站页面（例如 <https://space.bilibili.com/1643718>），右下角出现 ⏱ 悬浮球，点开即用

### 方式二：直接装脚本

把下面地址粘到浏览器地址栏，Tampermonkey 会自动弹出安装界面：

```
https://cdn.jsdelivr.net/gh/MolackTime/bili-follow-time@main/bili-follow-time.user.js
```

国内若 jsDelivr 缓存未刷新或不通，用镜像：

```
https://gh-proxy.com/https://raw.githubusercontent.com/MolackTime/bili-follow-time/main/bili-follow-time.user.js
```

### 方式三：下载文件手动导入

如果上面两种方式点了都没反应（网络受限、浏览器拦截、或不在 https 环境），可以直接下载脚本文件手动导入：

1. 在落地页点「**⤓ 下载 .user.js 文件**」，或自行保存
   <https://cdn.jsdelivr.net/gh/MolackTime/bili-follow-time@main/bili-follow-time.user.js>
2. 把下载到的 `bili-follow-time.user.js` **直接拖进浏览器窗口**，油猴会弹出安装界面
3. 或者打开油猴**管理面板 → 实用工具**，用「从 URL 安装」粘贴地址，或导入本地文件

> ⚠️ 油猴只会在「**https 地址上真实存在的 `.user.js` 文件**」上自动弹出安装界面。
> 通过 `file://` 本地文件、相对路径、或非 https 地址点安装，都不会有任何反应。

## 使用

| 场景 | 操作 |
|---|---|
| 查「我关注 TA 的时间」 | 面板 → **单个查询** → 粘贴主页链接 / 短链 / mid → 回车 |
| 拉取我的全部关注 | 面板 → **我的关注列表** → 输入框留空（自动识别账号），或粘贴你自己的主页链接 → 拉取 |
| 查某人的关注列表 | 面板 → **查 TA 的关注列表** → 粘贴对方主页链接（或 b23.tv 短链、直接填 mid）（需对方开放权限，最多 250 条） |
| 换个排序 / 只看某年 | 结果区顶部：点表头排序，下拉选年份 |
| 导出 | 结果区「导出 CSV」/「导出 JSON」 |
| 改参数 | 面板底部「⚙ 设置」 |

快捷键：`Alt` + `B` 开关面板。Tampermonkey 菜单里也有「打开查询面板 / 打开设置 / 恢复默认设置」。

> **未登录会怎样？** 脚本启动时会自动检测一次登录状态（调用 `x/web-interface/nav`）。
> 未登录时：悬浮球右上角出现红色 `!` 角标；打开面板顶部有黄色提示条 + 「去登录 / 重新检测」按钮；
> 点任何一个查询入口都会**先拦截并引导登录**，不会先发一堆注定失败的请求。
> 登录完成后点「重新检测」即可继续，**不需要刷新页面**。

## 为什么是用户脚本，而不是一个普通网页

这是本项目的核心约束，已实测确认（2026-09-30）：

| 事实 | 证据 |
|---|---|
| `api.bilibili.com` 只对 `*.bilibili.com` 的 Origin 返回 `Access-Control-Allow-Origin` + `Allow-Credentials: true` | `curl` 携带 `Origin: https://www.bilibili.com` → 200 且回显跨域许可头 |
| 对第三方 Origin（含 `*.github.io`）**直接拒绝且不返回任何跨域许可头** | `curl` 携带 `Origin: https://example.github.io` → 响应中不存在 `Access-Control-*` |
| 关系接口**必须登录**才返回真实 `mtime` | `curl https://api.bilibili.com/x/relation?fid=1` → `{"code":-101,"message":"账号未登录"}` |
| `Cookie` 是浏览器 forbidden header，网页无法手动携带 | MDN；且跨源页面本来就读不到 bilibili.com 的 Cookie |
| `www.bilibili.com` 无 CSP 头，`space.bilibili.com` 仅 `Report-Only` | `curl -I` 实测 → 页面上下文 `fetch` 没有 CSP 阻碍 |

**结论**：唯一干净的路径是让代码**运行在 bilibili.com 页面内部**，用同站 `fetch(url, { credentials: 'include' })`——Cookie / Referer / Origin 全部天然正确，请求特征与 B 站自身请求一致，最不容易触发风控。

> 顺带一提：即使套一层 Cloudflare Worker 代理，服务器也拿不到你的 SESSDATA（Cookie 属于 `.bilibili.com`），读者仍必须手动粘贴凭证，而且所有请求会从同一个出口 IP 发出，人一多必被风控。所以那条路不适合公开分发。

## 参数总表

全部参数都在设置面板里有 UI 入口（面板底部「⚙ 设置」）。所有输入都会做范围夹紧与默认值兜底，填错不会让脚本崩溃。

### A 组 · 查询

| 参数 | 默认 | 范围 / 选项 | 说明 |
|---|---|---|---|
| 每页条数 | `50` | 10–50 | 接口硬上限 50，调小反而增加请求次数。**查他人走兼容接口时此项无效**（服务端钉死 50） |
| 列表排序 | `按关注顺序` | 按关注顺序 / 按常访问 | 只影响接口返回顺序，不改变 `mtime`；仅对「自己」有效 |
| 最大翻页数 | `100` | 1–200 | 兜底保护，防无限翻页 |
| 最多拉取条数 | `0（不限）` | 0–100000 | 只想看「最近 N 个关注」时填 N |
| **查他人用哪个接口** | `兼容接口` | 兼容接口（上限 250）/ 标准接口（上限 100） | 见下方 FAQ |
| 查他人条数上限 | `250` | 1–250 | 受所选接口限制，设超了自动夹紧 |

### B 组 · 速度与网络

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 请求间隔 | `1700ms` | 300–10000ms | 五档预设（保守 2s / 标准 1.7s / 快速 1s / 极速 0.5s）+ 自定义 |
| 请求超时 | `20000ms` | 5000–60000ms | 网络差时调大 |
| 最大重试轮数 | `2` | 0–5 | 0 = 遇风控直接中止 |
| 风控退避起点 (-352) | `3000ms` | 1000–30000ms | 首次退避时长，后续按 1.6 倍递增 |
| 拦截退避起点 (-412) | `6000ms` | 1000–60000ms | 同上 |
| 退避随机抖动 | `100%` | 0–100% | 避免规律性重试被识别 |
| 强制走后台通道 | `关` | 开 / 关 | 页面请求异常时的自救开关 |

### C 组 · 解析与接口

| 参数 | 默认 | 说明 |
|---|---|---|
| 解析 b23.tv 短链 | `开` | 关闭后短链直接报错，速度略快 |
| 结果自动去重 | `开` | 按 mid 去重 |
| API 域名 | `https://api.bilibili.com` | ⚠️ 危险项，填错会导致全部失败 |

### D 组 · 显示与导出

| 参数 | 默认 | 选项 |
|---|---|---|
| 时间格式 | `YYYY-MM-DD HH:mm:ss` | 另含 `YYYY-MM-DD` / 相对时间（3 天前） |
| CSV 带 BOM | `开` | 关闭后 Excel 打开中文会乱码 |
| CSV 分隔符 | `逗号` | 逗号 / 制表符 |
| 导出字段 | 全部 | 昵称 / mid / 关注时间 / 距今 / 关系 / 关注时间戳 |
| 表格每屏行数 | `100` | 50 / 100 / 200 / 全部 |

### E 组 · 界面

| 参数 | 默认 | 选项 |
|---|---|---|
| 面板主题 | `跟随系统` | 跟随系统 / 浅色 / 深色 |
| 悬浮球位置 | `右下` | 右下 / 左下 / 右上 / 左上 / 隐藏 |
| 空间页自动提示 | `开` | 打开 UP 主主页时自动显示关注时间 |
| 记住面板状态 | `开` | 记住展开状态与上次输入 |

配置支持**一键导出 / 导入 JSON**（设置抽屉顶部按钮），方便备份或分享。存储使用 Tampermonkey 的 `GM_setValue` 而非 `localStorage`——B 站的 `www` / `space` / `t` 是不同 origin，`localStorage` 会各存各的导致设置丢失。

## 常见问题

**会不会盗号 / 上传数据？**
不会。脚本全文开源可审计，只做两件事：向 B 站只读接口发请求、在本地渲染表格。没有任何服务器收到数据，也不读取或存储你的 Cookie。

**会不会被风控 / 封号？**
只调用只读接口，不做任何写操作。默认 1.7s 限速，遇风控指数退避，连续失败自动中止。速度可调，但间隔越短风险越高。

**查出来的时间准确吗？**
`mtime` 精确到秒。注意**互粉或重新关注会刷新这个时间**，它表示「最近一次建立关注关系的时间」。

**为什么有时候查不到？**
常见原因：未登录（`-101`）、触发风控（`-352`）、IP 被拦截（`-412`）、对方未开放关注列表（`22115`/`22118`）。脚本会给出对应提示。

**「查 TA 的关注列表」最多能拿多少条？**
内置两条接口，可在设置里切换（默认兼容接口）：

| 接口 | 上限 | 说明 |
|---|---|---|
| **兼容接口**（默认） | **250** | `/x/v2/relation/followings`，可翻 5 页（`ps` 被服务端钉死 50）。第 6 页起返回 `22007「限制只访问前5页」`。读公开关注列表**无需登录** |
| 标准接口 | 100 | `/x/relation/followings`。⚠️ **超过 100 条时静默返回空列表、`code` 仍是 0**，很容易误以为对方只关注了 100 人 |

> 「自己」的关注列表**两条接口都给全量**，没有 250 的封顶。
>
> 兼容接口所在的域名不返回 CORS 响应头，所以它必须走油猴的后台请求通道——这也是本项目坚持用户脚本形态的另一个原因：纯网页连这个请求都发不出去。

**没登录的时候会有提醒吗？**
会，而且是主动提醒而不是等你查失败才说：启动检测一次 → 悬浮球红色角标 + 面板顶部提示条 → 点查询再前置拦截一次。错误码 `-101` 会被单独识别（而不是当成普通网络错误），直接渲染成「去登录 / 重新检测」按钮。另外区分了「确实未登录」和「网络异常导致无法确认登录状态」两种情况，不会误报。

**它会替我登录吗？**
不会。脚本不碰你的账号密码，也不做任何扫码或自动登录。点「去登录」只是帮你打开 B 站官方登录页（新标签页），登录动作完全由你自己完成。
